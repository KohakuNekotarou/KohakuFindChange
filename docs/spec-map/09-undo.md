# 09. Undo/Redo への追従

> コード地図での位置: ブロック **6b**（`model/KFCUndoFollow.*`）。
> KFC の書き込みが取り消しの1段であることは第6・7章、行の見た目は第4章。
> 訂正の書き方は [00-index.md](00-index.md)。

---

## 1. 何を追いかけるか

- **UNDO-01** ★**KFC 自身の書き込み**を「編集 > 取り消し／やり直し」（Ctrl+Z など）したとき、**一覧もそれに付いてくる**
  （2026-09-29 の作者の要望＝「取り消した後に、その行をもう一度却下できない。KCM のように一覧も戻ってほしい」）。
  - 訂正:

- **UNDO-02** 追いかける書き込み＝ Change Checked／行・ストーリー・文書の Replace／Replace Again／Reject Change／Accept Change／
  Accept All Changes by KohakuFindChange（どれも取り消しの1段＝GEN-16）。
  - 訂正:

- **UNDO-03** 取り消すと、その書き込みの**前の行**に戻る（置換した行は元の文字に戻ってチェックボックスも戻る・Change Checked なら置換の報告から検索の結果に戻る）。
  やり直すと、書き込みの**後の行**に戻る。却下した行を取り消すと「置換済み」に戻り、**その行の Reject Change がまた押せる**。
  - 訂正:

- **UNDO-04** ★**追いかけないもの** ―― KFC の書き込み**以外**のすべて：利用者の入力・ほかの操作の取り消し・変更履歴パネル・スクリプト、
  そして **Show Changes で一覧を作り直す前**に書いたもの（作り直した一覧は、それより前の書き込みの取り消しには付いてこない）。
  そのときは行をそのままにし、次に置換・却下・ジャンプするときの確かめ（版・行の文字・記録の時刻）が「変わった」と言う（REP-15・JMP-15・TRK-14）。
  ★Show Changes の一覧が、その前の書き込みの取り消しに付いてこない（文字は戻ったのに、行はそのままで、触るまで何も言わない）のは、
  **2026-10-04 の決定でいまのまま**（メッセージ欄で言う案・記録を読み直す案は採らなかった）。
  - 訂正:

## 2. どうやって知るか

- **UNDO-05** KFC の書き込みは、その取り消しの段の中に**目印**（何も変えないコマンド）を1つ入れる。取り消し・やり直しのたびに、その目印の知らせが文書から届き、KFC はそれで気づく。
  （目印は文書に保存されない＝実行時だけ。InDesign が知らせを配るのは文書ごとなので、文書に耳を付ける。）
  - 訂正:

- **UNDO-06** ★耳はストーリーではなく**文書**に付ける（2026-10-02 に直した）。ストーリーに付けていた頃は、文書を切り替えると InDesign がストーリーをメモリから外して耳が消え、
  2つ目の文書の Ctrl+Z を18回中12回聞き逃した。開いている文書は外されない。
  - 訂正:

- **UNDO-07** どの書き込みが取り消されたかは、**ストーリーの版**（本体の変更カウンタ）で見分ける ―― 取り消しは版を**ちょうど前の値**に戻し、やり直しはちょうど後の値に戻す
  （2026-08-08 の実測）。書き込みが動かしたストーリーがすべて「前」の版に戻っていれば取り消し、「後」に戻っていればやり直し。
  - 訂正:

- **UNDO-08** 行を戻すと、そのストーリーの**記録された版**も戻す ―― だから取り消しの後でも、置換・却下の確かめ（REP-15）はそのストーリーを「KFC が残したまま」と見なせる。
  - 訂正:

## 3. 順番と、追いかけをやめるとき

- **UNDO-09** 本体と同じ順で追いかける ―― 取り消しは**文書ごとに一番新しい**書き込みから、やり直しは一番古い取り消し済みのものから。
  Change Checked は複数の文書（章）にまたがるので、どの文書の取り消しにも当たる。1回の知らせで、いくつかの段をまとめて追いかけることもある。
  - 訂正:

- **UNDO-10** 覚えておく書き込みは**最大30**。そのうち一覧を丸ごと変えるもの（Change Checked）は**最後の3つ**まで（大きな検索は何千行もあるので）。
  それより古い書き込みは追いかけない（取り消しても行はそのまま）。
  - 訂正:

- **UNDO-11** 次のとき、覚えていた書き込みは**捨てる** ――
  新しい検索・Show Changes・文書やブックを閉じて**一覧が変わった**とき（別の一覧の行の話になるので）／
  その書き込みの文書が**閉じられた**とき（閉じると本体の取り消しの履歴も消えるので）／
  取り消した後に**新しい書き込み**をして、本体の履歴が切れたとき。
  - 訂正:

- **UNDO-12** All Documents の一覧で**1つの文書を閉じた**ときは、その文書の分だけを忘れ、ほかの文書の書き込みは追いかけ続ける（2026-09-29）。
  - 訂正:

- **UNDO-13** 検索・置換・Show Changes が**走っている間**と、KFC が書き込んでいる最中は、追いかけない（自分の書き込みの知らせは、書き終えたときに来る）。
  - 訂正:

- **UNDO-14** 行の並び（一覧の形）が書き込みのときと違うときは、その書き込みを捨てる（違う行に書き戻さないため）。
  - 訂正:

## 4. 画面

- **UNDO-15** 追いかけたら一覧を描き直し、メッセージ欄に書く ――
  1つなら `Undo: Replace - the rows are back as they were before it.`／`Redo: Reject Change - the rows are as they were after it.`
  （名前は `Change Checked`・`Replace`・`Replace Again`・`Reject Change`・`Accept Change`・`Accept All Changes by KohakuFindChange`）。
  いくつかなら `Undo: 3 changes of Kohaku Find/Change - the rows are back as they were before them.`、
  取り消しとやり直しが混ざれば `Undo / Redo: the rows follow the document (N undone, M redone).`
  - 訂正:

- **UNDO-16** Change Checked の取り消し・やり直しは一覧の**形が変わる**ので木を作り直す。ほかの書き込みは行を描き直すだけで、開いた・閉じた行はそのまま。
  - 訂正:

- **UNDO-17** 追いかけるのは**メインスレッドだけ**（バックグラウンドの書き出しには取り消しも一覧も無い）。
  - 訂正:

- **UNDO-18** ⚠取り消しの知らせは InDesign が**手の空いたとき**に配るので、一覧が戻るのは Ctrl+Z の**少し後**
  （回帰試験は取り消しの後に待ってから読む。すぐ読むと約1割取りこぼした＝2026-09-29 実測）。
  - 訂正:

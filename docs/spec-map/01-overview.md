## 1. この製品は何をするか

- **GEN-01** InDesign 本体の「検索と置換」の設定のまま、**文書（「検索:」が指す範囲）か、ブックの全章を一度に**検索し、
  一致した箇所をパネルの木に一覧するパネル。
  - 訂正:

- **GEN-02** 一覧の行をクリックすると、その箇所へ画面が移動して印が出る。**チェックを付けた行だけ**を置換できる。
  ★**行は最初、すべてチェックが外れている**（置換するものは利用者が選ぶ・2026-09-27 の決定）。
  - 訂正:

- **GEN-03** ★**検索条件を入力する欄はパネルに無い。** 何を探すか（検索文字列・タブ・オプション・書式）は、
  すべて本体の「編集 > 検索と置換」から読む。
  何も実行していないパネルのメッセージ欄は、それを案内する一文
  （`Type what to find in Edit > Find/Change, then run Find from this panel's menu.`）を出す。
  - 訂正:

- **GEN-04** 本体の「検索と置換」ダイアログは、パネルメニュー先頭の **Open Find/Change...** でも開ける。
  **文書が1つも開いていなくても開く**（本体の「編集」メニューでは灰色になる状態でも）。
  最小化してあったダイアログは、閉じずに元へ戻す。
  ★**本体のメニューには手を入れない**（本体の項目を灰色にさせない方式は 2026-10-01 に試して外した）。
  - 訂正:

- **GEN-05** 置換は本体の置換の設定で書き（置換文字列。字形タブなら置換字形、文字種変換タブなら置換後の文字種）、
  **すべて変更履歴（Track Changes）に記録する**。記録の作成者は **`KohakuFindChange`**。
  ⚠**脚注の中だけは例外** ―― InDesign が脚注の中の変更を記録しないので、置換はされるが記録は残らない（行に `no track` と出る）。
  - 訂正:

- **GEN-06** 一覧が消えても、**文書に残った記録から一覧を作り直せる**（**Show Changes by KohakuFindChange**）。
  新しい検索をした後・文書を閉じて開き直した後・InDesign を再起動した後でも。
  ただし作り直した一覧では**置換はできず**、却下（Reject）と承認（Accept）だけができる。→ 第8章
  - 訂正:

  - 訂正:

  ⇒ **model だけを入れても壊れない**（パネルが無いので操作はできない）。逆に UI だけでは動かない。
  - 訂正:

- **GEN-14** ★**頼みごとの口が無いとき（バックグラウンドスレッド・InDesign Server）、model は「UI なし」として動く** ――

## 3. 文書に何を書くか

- **GEN-15** **検索は読むだけ。** 文書を歩く間は「入る前に未変更だった文書は、未変更に戻す」形で囲んである（`SaveRestoreModifiedState`）。
  Show Changes も同じで、読んだ章が変更済みになって出てくることはない。
  - 訂正:

- **GEN-16** 文書の中身を変える操作は次のものだけ ――
  **Change Checked**／行のメニューの **Replace**（ヒット・ストーリー・文書の行）／**Replace Again (Current Find/Change Settings)**（ストーリー・文書の行）／
  **Reject Change by KohakuFindChange** とその仲間（`… in This Story`／`Reject All Changes by KohakuFindChange in This Document`／`… in This Run`）／
  **Accept Change by KohakuFindChange** とその仲間（`… in This Story`／`… in This Run`／`Accept All Changes by KohakuFindChange in This Document`）。
  **どれも1回が「編集 > 取り消し」の1段**になる。
  書き込みが失敗して**巻き戻ったときは、本文と一緒に「変更あり」の印も入る前の状態に戻す**（Change Checked のキャンセルも、行のメニューの「全部か無し」も）
  ＝保存済みの文書が、何も変わっていないのに未保存になることは無い。
  （行のメニューの側には無く、印が残っていたのを 2026-10-04 に直した＝R9-1。→ 第6章）
  - 訂正:

- **GEN-17** ★**何も保存しない。** 置換が入った文書は「変更あり・未保存」のまま残し、上書きするかどうかは利用者が決める。
  （置換の後に保存するオプションは 2026-08-05 に撤去した。）
  Change Checked は、**KFC が窓なしで開いた章に置換が入ったら、窓を開く**（見えないと保存も閉じるもできないため）。
  開けなかったら ` N chapter(s) were changed but could not be shown - open them from the book panel to save them.` と書く。
  ★**利用者が窓なしで持っている文書（All Documents）は、窓を開かずにそのまま残し**、` N document(s) without a window were changed - still hidden.` と書く
  （2026-09-29 の決定＝重いので隠しているのかもしれない）。
  行のメニューの Replace（Replace Again も）も**同じ規則**で、隠した文書は隠したまま（メッセージ欄に ` The document has no window - still hidden.`）。
  閉じていた章で行の Replace が**断られた・巻き戻ったとき**は、窓を付けずに閉じて返す。
  （行のメニューは隠した文書にも、断られた章にも窓を開いていたのを、2026-10-04 に直した＝D9-1・R9-2。→ 第6章）
  - 訂正:

- **GEN-18** 置換を書くとき、その文書のユーザー一覧に **`KohakuFindChange` を UI カラー Amber（琥珀色）で**登録する（すでに Amber なら何もしない）。
  InDesign のユーザー名と、利用者自身の色は変えない。この登録も、置換と同じ取り消しの1段に入る。
  - 訂正:

- **GEN-19** **変更履歴の記録と、その作成者の色は、文書のデータとして残る**（保存すれば `.indd` に入る）。
  記録が残るから、Show Changes が後から一覧を作り直せる。
  一方、**KFC 独自の形のデータは文書に書かない**。取り消し・やり直しに一覧を付いてこさせるための見張り（observer）も、
  実行時に付けるだけで文書には書き込まれない。
  - 訂正:

## 4. 検索条件は本体の「検索と置換」から読む

- **GEN-20** 検索できるタブは **テキスト（Text）・正規表現（GREP）・字形（Glyph）・文字種変換（Transliterate）** の4つ。
  **オブジェクト（Object）・カラー（Colour）** のタブでは Find in … が灰色になる（どちらもページアイテムを探すタブで、このパネルが一覧するのはテキストのため）。
  ★オブジェクトのタブを扱う案（`IObjectWalker`）はやらないと決めた（2026-10-03）。
  - 訂正:

- **GEN-21** KFC が本体の「検索と置換」の設定に書き込むのは次の3つだけ ――
  ①検索・置換の直前に、**今のタブを今と同じ値で確定し直す**（字形タブなら検索字形、文字種変換タブなら検索文字種も。置換のときは置換側の字形・文字種も）。
  これをしないと、パネルから動かした検索は画面のタブに関係なく「テキスト」として走る。
  ②検索・置換の間だけ**検索方向を前向きにし、終わったら利用者の設定に戻す**。
  ③**アプリケーションバーの検索欄で Enter** したとき、その欄の文字を検索文字列に入れる（テキスト／正規表現のタブのときだけ）。→ 第15章
  （Translucent Find/Change・Minimizable Find/Change は設定ではなく、ダイアログの**窓の見た目**に作用する。→ 第13章）
  - 訂正:

- **GEN-22** ★**検索・置換は前向きだけ**（2026-09-26 の決定。一覧には向きの意味が無いため）。
  ダイアログの「後方へ検索」の設定は、KFC の動きを何も変えない。（例外は置換が書くときの歩き方1つ → 第6章）
  - 訂正:

- **GEN-23** ★**「検索:」の欄は書き換えない**（その欄を書き換えるコマンドは使わない ―― 利用者に見える欄が変わる副作用しか無いため）。
  - 訂正:

## 6. 用語と状態

- **GEN-29** 一覧の木は最大5段 ――
  **ブックの行**（ブックを検索したときだけ）→ **文書の行**（章）→ **run の行**（Show Changes で作り直した一覧だけ）→ **ストーリーの行** → **ヒットの行**。
  - 訂正:

- **GEN-30** 一覧はいつも次の3つのどれかの状態にある ――
  ①**作業リスト**＝検索の結果。ヒットの行にチェックボックスがある。
  ②**置換の報告**＝Change Checked の後。その置換に関わった行（置換した行・置換できなかった行とその理由）と、
  ロックされた行・すでに何か言うことのある行だけが残り、**チェックボックスは消える**。
  却下（Reject）で元に戻した行だけはチェックボックスが戻り、もう一度置換できる。
  ③**記録から作り直した一覧**＝Show Changes の後。チェックボックスは無く、置換はできない。
  ⚠**行のメニューの Replace（1行・ストーリー・文書）では②にならない** ―― 一覧は作業リストのまま。
  - 訂正:

- **GEN-31** **run**＝置換1回分（Change Checked の1回、または行のメニューの Replace／Replace Again の1回）。
  その記録には run が始まった時刻が付き、行ごとに 100 ナノ秒ずつずらした時刻で1行ずつ見分ける。
  - 訂正:

- **GEN-32** **保持中（held）の章**＝KFC が窓なしで開いた章。KFC が閉じてよいのはこれだけ。
  **窓が付いた瞬間に利用者のものになり**、KFC はもう閉じない。利用者が自分で開いていた章は、最初から保持しない。
  - 訂正:

- **GEN-33** 1度に走るのは**検索・置換・Show Changes のうち1つだけ**。
  走っている間（進捗バーが出ている間）は KFC のメニュー項目がすべて灰色になり、それでも割り込んできた操作（検索・置換・行のメニューの書き込み）はメッセージ欄に理由を出して断る。
  - 訂正:

- **GEN-34** ★件数の上限は **1つ＝5,000 行**（2026-10-04 から）。
  **1回の検索（Show Changes も）で集めるのは 5,000 行まで**で、それがそのまま**パネルに描く上限**でもある ―― 集めた行はすべてパネルの一覧に載る。
  上限で止まると、メッセージ欄に ` Stopped at the 5000 safety limit - narrow your search.` と出す（Show Changes は ` Stopped at the 5000 safety limit.`）。
  それより先の一致は一覧に入らない ―― 置換した後でもう一度検索すれば、残りが見つかる。
  ⇒ ブックの行・文書の行の Check All も、その後の Change Checked も、**パネルの一覧に載っている行にしか届かない**（スクロールの外の行は一覧に載っている）。
  （それまでは集める上限が 10,000 で、描かない 5,001 行目から先にも Check All でチェックが付き、Change Checked が置換していた。
  差は Save Results…＝2026-09-27 に撤去＝に全行を渡すために残っていたもので、撤去の後は害しか無かった。）
  - 訂正: ✅2026-10-04 対応（**コードを変更**）→ 集める上限を描く上限と同じ 5,000 にした（`kKFCCollectHitLimit = kKFCDisplayHitLimit`・`c05b0e5`）。
    5,100 件の文書で実機確認＝5,000 行で止まり、全行が画面に出て、上の文がメッセージ欄に出た（回帰 190/190・悪化0）。規則文を書き直した

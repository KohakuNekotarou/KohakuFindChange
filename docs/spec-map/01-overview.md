## 3. 文書に何を書くか

- **GEN-15** **検索は読むだけ。** 文書を歩く間は「入る前に未変更だった文書は、未変更に戻す」形で囲んである（`SaveRestoreModifiedState`）。
  - 訂正:

- **GEN-16** 文書の中身を変える操作は次のものだけ ――
  行の **Replace**（ヒットの行の右クリックのメニュー／行を選んで Return キー。1.4.0 から、まとめて選んだ行も＝REP-36）／**Change All in Book (No List)**／クエリ連続実行（パネルメニューの **Run Saved Queries...**＝第16章。2026-10-07 にダイアログができた＝それまではテスト用の入口だけだった）。
  **どれも1回が「編集 > 取り消し」の1段**になる（Change All in Book はブック全体で1段・まとめて選んだ行の置換とクエリ連続実行は、文書がいくつでも全体で1段）。
  書き込みが失敗して**巻き戻ったときは、本文と一緒に「変更あり」の印も入る前の状態に戻す**（Change All in Book のキャンセルも、行の Replace の失敗も）
  ＝保存済みの文書が、何も変わっていないのに未保存になることは無い。
  （行のメニューの側には無く、印が残っていたのを 2026-10-04 に直した＝R9-1。→ 第6章）
  （2026-10-06 に外した＝Change Checked・ストーリーと文書の行の Replace・Replace Again・Reject／Accept の仲間。F2・F16）
  - 訂正:

- **GEN-17** ★**何も保存しない。** 置換が入った文書は「変更あり・未保存」のまま残し、上書きするかどうかは利用者が決める。
  （置換の後に保存するオプションは 2026-08-05 に撤去した。）
  **KFC が窓なしで開いた章に置換が入ったら、窓を開く**（見えないと保存も閉じるもできないため）。何も書かなかった章は閉じて返す。
  ★**利用者が窓なしで持っている文書（All Documents）は、窓を開かずにそのまま残し**、` The document has no window - still hidden.` と書く
  （2026-09-29 の決定＝重いので隠しているのかもしれない）。
  閉じていた章で行の Replace が**断られた・巻き戻ったとき**は、窓を付けずに閉じて返す。
  （行のメニューは隠した文書にも、断られた章にも窓を開いていたのを、2026-10-04 に直した＝D9-1・R9-2。→ 第6章）
  - 訂正:

- **GEN-18** （2026-10-06 に外した＝第7章 TRK-26。それまでは置換のたびに作成者 `KohakuFindChange` を UI カラー Amber で登録していた）
  - 訂正:

- **GEN-19** **KFC 独自の形のデータは文書に書かない。** 取り消し・やり直しに一覧を付いてこさせるための見張り（observer）も、
  実行時に付けるだけで文書には書き込まれない。（それまでに KFC が付けた変更履歴の記録は文書に残る＝第7章 TRK-29。）

## 4. 検索条件は本体の「検索と置換」から読む

- **GEN-20** 検索できるタブは **テキスト（Text）・正規表現（GREP）・字形（Glyph）・オブジェクト（Object）・文字種変換（Transliterate）** の5つ。
  **カラー（Colour）** のタブでは Find in … が灰色になる。★オブジェクトのタブは 1.4.0 から（2026-10-09 作者の依頼で 10-03 の「やらない」を覆した＝第17章）。（1.4.0・17-objects.md）
  （1.3 まで：検索できるタブは **テキスト（Text）・正規表現（GREP）・字形（Glyph）・文字種変換（Transliterate）** の4つ。
  **オブジェクト（Object）・カラー（Colour）** のタブでは Find in … が灰色になる（どちらもページアイテムを探すタブで、このパネルが一覧するのはテキストのため）。
  オブジェクトのタブを扱う案（`IObjectWalker`）はやらないと決めていた（2026-10-03）。）
  - 訂正:

- **GEN-21** KFC が本体の「検索と置換」の設定に書き込むのは次の3つだけ ――
  ①検索・置換の直前に、**今のタブを今と同じ値で確定し直す**（字形タブなら検索字形、文字種変換タブなら検索文字種も。置換のときは置換側の字形・文字種も）。
  これをしないと、パネルから動かした検索は画面のタブに関係なく「テキスト」として走る。
  ②検索・置換の間だけ**検索方向を前向きにし、終わったら利用者の設定に戻す**。
  ③**アプリケーションバーの検索欄で Enter** したとき、その欄の文字を検索文字列に入れる（テキスト／正規表現のタブのときだけ）。→ 第15章

  - 訂正:

  ダイアログの「後方へ検索」の設定は、KFC の動きを何も変えない。（例外は置換が書くときの歩き方1つ → 第6章）

## 1. 文書を閉じたとき

- **LIFE-01** ★**文書の結果**（Book Scope OFF で検索した結果）は、**その文書を閉じるとその行が消える**。
  閉じた文書の行を残すと、クリックで黙って開き直し、行の Replace で書き込んでしまうため。目玉の付いた行も消える（ROW-45＝目玉が残すのは探し直しから）。
  ★**段の見出しは残る**（2026-10-14 夜の作者の決定「題名の部分は残る」「ドキュメント部分だけが閉じられたドキュメントだけ消える」）＝今の段は見出しだけ `[Text] F:"…" C:"…"  (0/0)` になり、メッセージ欄＝`<文書名> was closed - its rows are gone.`。灰色の段（履歴の段）からも、その文書の行がその場で消え、見出しの数が今の数になる（ROW-40）。見出しだけの段も、クリックで切り替わり、Clear These Results で消せる。★文書を開き直せば、見出しの右クリックの Search These Results Again で、その段の条件でその文書をもう一度探し、行が戻る（ROW-44＝閉じたときのファイルで開いている文書を見つける・KFC は開かない）。
  一覧ごと消える（`Results cleared - the document was closed.`）のは、段でない一覧（行が残らず、検索で作った一覧でもない＝ROW-41）だけ。それまでは、文書の結果は見出しごと消え、灰色の段には閉じた文書の行が写しのまま残っていた（作者の依頼②）。

## 2. ブックを閉じたとき

- **LIFE-09** ★**ブックの結果**は、**そのブックを閉じると消える**（`Results cleared - the book was closed.`）。
  一致が0件だったブックの検索でも、ブックの行が残っているので、それも消える。
  - 訂正:

- **LIFE-10** ブックを閉じると、KFC がそのブックのために開いて、**窓の無いまま残っている章**があれば、それも**閉じて返す**
  （一覧に何が出ていても。窓の無い章は、残すと `.indd` のロックが残り、利用者には見えも閉じもできないので）。
  ブックの結果を出していなければ、一覧には触らない（文書の結果を出していれば、そのまま）。
  ⚠**ふつうは残っていない** ―― 検索・行の Replace・Change All in Book は、窓なしで開いた章を、終わるまでに閉じて返すか、窓を付けて利用者に渡す（SCOPE-10・REP-24）。
  窓の無いまま残るのは、**失敗したときだけ**：
  ①ジャンプや文書の行のクリックで閉じた章を開き直したのに、窓を開けなかった（`Cannot bring that chapter's window to the front.`）
  ＝★1.4.0（2026-10-10）から**残らない**：窓を出せずに終わった着地は、その場で閉じて返す（JMP-12）
  ②置換が書いたのに窓を開けなかった（⚠2026-10-06 から、メッセージ欄はこれを言わない＝Change Checked の文
  ` … chapter(s) were changed but could not be shown - open them from the book panel to save them.` と一緒に消えた。
  Change All in Book・行の Replace・クエリ連続実行は、窓を開けなかったことを数えていない）
  ③本体が閉じるのを断った。
  ②は置換が入って未保存なので、ブックを閉じても**閉じない**（閉じると黙って消えるため・SCOPE-18）。このときの「返す」は、①③の取り残しを片づける安全網。
  - 訂正: ✅2026-10-04 回答 → **ふつうは無い。失敗したとき（窓を開けなかった・閉じるのを断られた）だけ残る**。どんなときに残るかを本文に書き足した（地図の書き落とし＝A）

- **LIFE-11** 「閉じたのはどのブックか」を InDesign は知らせてこないので、KFC は**ブックが閉じるたびに「検索したブックがまだ開いているか」を聞く**。
  閉じる知らせの瞬間はまだ開いているように見えるので、**約0.3秒後**に聞く。ほかのブックが閉じただけなら何もしない。
  - 訂正:

- **LIFE-12** ブックを閉じたのが検索・行の Replace・Change All in Book の**走っている最中**なら、終わるまで待ってから聞く。
  ★**行のクリックの着地の最中も待つ**（2026-10-12・作者「直せるなら治して欲しい」＝提案 P-A）＝着地は章や窓を開くあいだメッセージループを回すので、0.3秒後の問いがその中に来ると、着地が読んでいる一覧を消し、開いている途中の章（まだ窓が無い）を返してしまいうる。着地は UI 側の印なので、model 側の見張りは UI 側に「いま着地の最中か」を聞いて（`IKFCUIServices::IsLanding`）、そうなら0.3秒ずつ待ち直す。⚠着地の中で 0.3秒の問いが走るかどうかは測っていない（守り）。
  - 訂正:

- **LIFE-13** ★⚠**ブックを別名で保存した後**は、ブックの行のクリックが `That book is no longer open.` と言い、**別のブックを閉じただけで一覧が消える**
  （KFC が覚えている「検索したブック」のパスが古いままになるため）。章の行のジャンプと置換は、章のファイルで引くので動く。
  ＝**2026-10-03 の決定でいまのまま**（別名で保存するのはまれなので。ブックには ID が無く、直すなら別名で保存のコマンドを横取りすることになる）。
  - 訂正:

## 3. 保存したとき

- **LIFE-14** 文書やブックを**保存しても、結果は何も変わらない**（KFC は保存に何もしない）。
  ★ただし**文書を別名で保存すると、その文書の行の名前が、その場で新しいファイル名になる**（2026-10-11 夜の作者の決定・`KFCSaveAsDocResponder`＝InDesign の「別名で保存の後」の知らせ）。
  行はそれまでも文書そのもの（データベース）を指していて、置換・Search This Document Again・閉じたときの文もその文書のもの＝名前だけが検索のときのままだった
  （B.indd を C.indd に別名で保存し、B.indd を開き直すと、「B.indd」の行が C.indd に書いていた＝正しい文書に、紛らわしい名前で）。
  閉じたときの文（LIFE-02）も新しい名前で言う。一度も保存していない文書を初めて保存したときも同じ（名前の無い文書 → ファイル名）。
  **「コピーを保存」では変えない**（文書は元のファイルのまま）。**ブックの結果の章の行は変えない**（行はブックに載った章のファイルのもの・章を別名で保存した写しは章ではない＝xs3-e-saveas-jump-replace）。
  クエリの連続実行の取り消しのために取ってある一覧の写しも同じ名前にする（取り消しで古い名前が戻らない）。段（灰色の段）に取ってある一覧も同じ名前にする（切り替えで古い名前が戻らない＝2026-10-19 から・ブロック11 の不具合の回の D11-2）。KFC の実行の最中には変えない（その間の一覧は実行のもの＝閉じたときと同じ決まり。実行の進捗バーが出ている間は人は保存できず、KFC 自身は保存しない）。
  ブックかどうかは一覧に聞く（閉じたときと同じ問い）＝章のファイルの有無では決めない（ブックの章でもファイルを名指せないことがある）。
  回帰＝`doc-saveas-replace`／`doc-saveas-docagain-name`／`doc-untitled-save-name`／`doc-saveacopy-keeps-name`／`ad-saveas-open-replace`／`ad-saveas-reopen-replace`。
  - 訂正:
